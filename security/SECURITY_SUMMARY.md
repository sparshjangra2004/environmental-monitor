# EcoMonitor Security Implementation

## Overview

EcoMonitor implements 13 security features across authentication, API protection, input validation, and audit logging. All features are implemented from scratch in PHP — no third-party security libraries.

---

## Feature 1 — OTP Two-Factor Authentication

**Files:** `auth/login.php`, `auth/otp_verify.php`  
**Table:** `otp_tokens`

After password verification, a 6-digit OTP is generated:
```php
str_pad(random_int(0, 999999), 6, '0', STR_PAD_LEFT)
```
Stored in `otp_tokens` with `expires_at = NOW() + 5 minutes` and a `used` flag to prevent reuse. The user is redirected to `otp_verify.php` to enter the code. Only on correct OTP does `completeLogin()` run.

---

## Feature 2 — Forgot Password / Secure Reset

**Files:** `auth/forgot_password.php`, `auth/reset_password.php`  
**Table:** `password_resets`

A 64-character hex token is generated: `bin2hex(random_bytes(32))`. Stored with a 1-hour expiry. The same success message is shown whether the email exists or not (prevents email enumeration). On reset, the token is marked `is_used = 1` immediately so it cannot be reused.

---

## Feature 3 — JWT API Authentication

**Files:** `config/jwt.php`, `api/auth.php`, `api/readings.php`, `admin/api_demo.php`

Manual JWT implementation — no library. Structure: `header.payload.signature` (base64url encoded, dot-separated).

- **Sign:** `hash_hmac('sha256', "header.payload", JWT_SECRET, true)`
- **Verify:** re-sign the received header+payload and compare with `hash_equals()` (timing-safe)
- Token payload includes: `sub` (user ID), `role`, `iat` (issued at), `exp` (expiry)
- API endpoints read `Authorization: Bearer <token>` header

---

## Feature 4 — Session Security

**File:** `includes/session.php`

- `session_set_cookie_params(['httponly' => true, 'samesite' => 'Strict'])` before `session_start()`
- `session_regenerate_id(true)` on login (prevents session fixation)
- 30-minute inactivity timeout (`SESSION_TIMEOUT = 1800`)
- `last_activity` timestamp updated each request; if elapsed > timeout → destroy session → redirect to `login.php?expired=1`

---

## Feature 5 — SQL Injection Prevention

**File:** `security/sql_injection_demo.php`

Every database query uses MySQLi prepared statements. The `?` placeholder is never treated as SQL syntax — only as a bound value. Demo page shows side-by-side: vulnerable string concatenation vs. protected prepared statement, with live execution of both.

---

## Feature 6 — Input Sanitization

**File:** `config/sanitize.php`

Four sanitization functions:
- `sanitizeString()` — `strip_tags` + `htmlspecialchars_decode` + `trim`
- `sanitizeEmail()` — `FILTER_SANITIZE_EMAIL` + `FILTER_VALIDATE_EMAIL`
- `sanitizeInt()` — `FILTER_VALIDATE_INT` with null fallback
- `sanitizeFloat()` — `FILTER_VALIDATE_FLOAT` with null fallback

All output to HTML uses `htmlspecialchars()` to prevent XSS.

---

## Feature 7 — CSRF Protection

**File:** `config/sanitize.php`

Every POST form includes a hidden `csrf_token` field generated by:
```php
$_SESSION['csrf_token'] = bin2hex(random_bytes(32));
```
Server validates with `hash_equals()` (timing-safe comparison). `csrfField()` outputs the hidden input. `validateCSRFToken()` validates. Applied to: login, register, forgot password, reset password, all admin forms.

---

## Feature 8 — CORS Protection

**File:** `config/cors.php`

API endpoints only accept cross-origin requests from a whitelist of localhost origins. The `Access-Control-Allow-Origin` header is only set to the matched origin (not `*`). OPTIONS preflight requests are handled. `Content-Type: application/json` is forced on all API responses.

---

## Feature 9 — IP Blocking

**Files:** `security/ip_blocker.php`, `admin/ip_management.php`  
**Table:** `blocked_ips`

`isIPBlocked()` is called from `includes/session.php` on every page load. If blocked: outputs a 403 HTML page and calls `exit()`. Admin can block/unblock IPs from the management page. Uses a soft-delete model (`is_active` flag) so block history is preserved.

---

## Feature 10 — Login Attempt Monitoring

**File:** `admin/login_attempts.php`  
**Table:** `login_attempts`

Every login attempt (success or failure) is recorded with email, IP, success flag, and timestamp. After 5 failures within 15 minutes, the account is locked for that window. Admin dashboard shows total attempts, success/failure counts, and currently locked accounts.

---

## Feature 11 — Security Event Logging

**Files:** `security/logger.php`, `admin/security_logs.php`  
**Table:** `security_logs`

`logActivity(?int $userId, string $action, string $details)` inserts a row for every significant event: successful/failed login, OTP attempts, password changes, JWT issuance, IP blocks, API access. Errors are silently ignored — logging never crashes the application.

---

## Feature 12 — Rate Limiting

**File:** `security/rate_limiter.php`  
**Table:** `rate_limits`

60 requests/minute per IP per endpoint. Uses `INSERT ... ON DUPLICATE KEY UPDATE request_count = request_count + 1`. If `window_start < NOW() - 60s`: reset counter. If `request_count > 60`: return HTTP 429 with JSON error. Applied to all `api/` endpoints.

---

## Feature 13 — Security Audit Checklist

**File:** `security/security_audit.php`

Live checklist page that uses `file_exists()` and `SHOW TABLES LIKE` to verify the status of every security file and database table. Shows pass/fail for all 13 features with implementation details.

---

## SQL Tables to Create in phpMyAdmin

Run these in **phpMyAdmin → EcoMonitor database → SQL tab**:

```sql
-- Feature 1: OTP tokens
CREATE TABLE otp_tokens (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    otp_code VARCHAR(6) NOT NULL,
    expires_at DATETIME NOT NULL,
    is_used TINYINT(1) DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Feature 2: Password resets
CREATE TABLE password_resets (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    token VARCHAR(64) NOT NULL UNIQUE,
    expires_at DATETIME NOT NULL,
    is_used TINYINT(1) DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- Feature 9: Blocked IPs
CREATE TABLE blocked_ips (
    id INT AUTO_INCREMENT PRIMARY KEY,
    ip_address VARCHAR(45) NOT NULL,
    reason VARCHAR(255),
    blocked_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    blocked_by INT DEFAULT NULL,
    is_active TINYINT(1) DEFAULT 1
);

-- Feature 10: Login attempts
CREATE TABLE login_attempts (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255),
    ip_address VARCHAR(45),
    success TINYINT(1) DEFAULT 0,
    attempted_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Feature 11: Security logs
CREATE TABLE security_logs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT DEFAULT NULL,
    action VARCHAR(100) NOT NULL,
    ip_address VARCHAR(45),
    user_agent TEXT,
    details TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Feature 12: Rate limits
CREATE TABLE rate_limits (
    id INT AUTO_INCREMENT PRIMARY KEY,
    ip_address VARCHAR(45) NOT NULL,
    endpoint VARCHAR(255) NOT NULL,
    request_count INT DEFAULT 1,
    window_start TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY unique_ip_endpoint (ip_address, endpoint)
);
```
